# DAON 기억 시스템 — 쉽게 읽는 보고서

> 작성일: 2026-07-30
> 대상: DAON Agent System의 장기 기억(Memory) 기능
> 핵심 코드: [`api/api/memory_store.py`](../api/api/memory_store.py)

---

## 1. 한 줄 요약

**DAON의 기억 시스템은 "사람의 메모장"이 아니라 "AI의 작업 기억"입니다.**
대화에서 중요한 정보를 AI가 스스로 뽑아 저장하고, 다음 대화 때 AI가 스스로 다시 불러와 사용합니다. 사람은 거의 손댈 필요가 없습니다.

---

## 2. 왜 만들었나 (해결하고 싶었던 문제)

일반적인 AI 챗봇은 **대화가 끝나면 모든 것을 잊습니다.**
어제 "나는 파이썬 개발자이고, 한국어로 답변해줘"라고 말해도 오늘은 다시 처음부터 설명해야 합니다.

DAON은 이 문제를 다음 방식으로 해결합니다.

| 기존 챗봇 | DAON 기억 시스템 |
|---|---|
| 대화 종료 = 완전 망각 | 대화 종료 시 핵심을 자동 저장 |
| 매번 같은 설명 반복 | 다음 대화에서 자동으로 불러옴 |
| 사용자가 일일이 기록 | AI가 스스로 추출 |
| 기록이 쌓이기만 함 | 자동 정리·중복 제거·모순 해결 |

---

## 3. 가장 중요한 철학: "AI의 작업 기억"

이 시스템을 이해하는 핵심은 **기억의 1차 소비자가 사람이 아니라 AI**라는 점입니다.

- **1차 소비자 = AI**: 저장된 기억은 AI의 시스템 프롬프트에 자동으로 주입되어, AI가 답할 때 바로 참고합니다.
- **2차 소비자 = 사람**: 사람은 필요할 때 들여다보거나, 잘못된 기억을 지우는 정도만 합니다.

그래서 이 시스템은 "예쁘게 정리된 노트"를 만드는 것이 목표가 아닙니다.
**"AI가 다음 대화에서 무엇을, 언제, 얼마나 불러와야 하는가"** 가 핵심입니다.

### 역할 분리 (중요)
- **AI 기억** = 이 시스템(SQLite, 자동 추출). AI가 쓰는 작업 기억.
- **사람 기록** = 옵시디언·노션 등. 사람이 쓰는 영구 기록.
- 둘은 섞지 않습니다. 내보내기는 사용자가 명시적으로 요청할 때만 합니다.

### 무결성 원칙
| 행위 | 허용? | 이유 |
|---|---|---|
| 삭제 ("이거 잊어줘") | ✅ | 깨끗한 망각 |
| 파일 직접 편집 | ❌ | AI가 모르는 수정 = 기억 오염 |
| 새 학습 (대화) | ✅ | 자연스러운 갱신 |

---

## 4. 어떻게 동작하나 (3단계 흐름)

전체 흐름은 **추출 → 저장 → 주입** 의 순환입니다.

```
   대화 시작 ──────────────────────────── 대화 종료
      │                                      │
      │ ③ 주입 (불러오기)                     │ ① 추출 (뽑아내기)
      │    build_memory_prompt()             │    process_session_async()
      ▼                                      ▼
 ┌──────────┐                          ┌──────────────┐
 │ AI 시스템 │ ◄── ② 저장 ──────────── │  백그라운드   │
 │  프롬프트 │      memory.db          │   추출 워커   │
 └──────────┘                          └──────────────┘
```

### ① 추출 — 대화가 끝나면 자동으로 뽑는다
채팅이 끝나면 [`process_session_async()`](../api/api/memory_store.py:1663)가 호출됩니다.

- 사용자 턴이 **2개 미만**인 짧은 대화는 저장 가치가 낮다고 보고 건너뜁니다.
- 대화 내용을 통째로 **작업 큐(job_queue)** 에 등록합니다.
- 실제 추출은 **백그라운드 상주 워커**가 순서대로 처리합니다.
  - 여러 채팅이 동시에 끝나도 쓰기 충돌이 나지 않도록 워커는 1개만 둡니다.
  - 실패하면 지수 백오프(5초 → 30초 → 120초)로 최대 3번 재시도합니다.

워커는 세 가지를 뽑습니다:
1. **장기 기억(facts)** — "사용자는 파이썬 개발자다" 같은 핵심 사실
2. **사용자 프로필(profile)** — 이름, 직업, 선호 언어 등 정해진 9개 항목
3. **세션 요약(summaries)** — 그 대화의 줄거리 (세션당 1건만 유지)

### ② 저장 — SQLite 한 파일에 모은다
모든 기억은 [`STATE_DIR/memory.db`](../api/api/memory_store.py:30) 라는 SQLite 파일 하나에 저장됩니다.
(설치판은 `LOCALAPPDATA`, 개발 환경은 `data/` 폴더)

### ③ 주입 — 다음 대화 때 자동으로 불러온다
새 채팅이 시작되면 [`build_memory_prompt()`](../api/api/memory_store.py:722)가
현재 사용자가 보낸 메시지를 분석해 **관련 있는 기억만 골라** AI에게 주입합니다.

## 5. 무엇을 저장하나 (저장 구조)

`memory.db` 안에는 다음 표들이 있습니다.

| 테이블 | 역할 | 비유 |
|---|---|---|
| `facts` | 핵심 사실들 | AI가 아는 "사실 카드" |
| `profile` | 사용자 프로필 (정규 key 9개) | AI가 아는 "사용자 이력서" |
| `summaries` | 세션별 대화 줄거리 | 대화 "요약 노트" |
| `job_queue` | 처리 대기 중인 추출 작업 | 할 일 "대기열" |
| `fact_usage` | 어떤 기억을 언제 주입했는지 | 기억 "사용 일지" |
| `refine_log` | 자동 정리 이력 | 정리 "작업 기록" |
| `memory_review` | 사람 확인이 필요한 항목 | "검토 대기함" |
| `agent_inbox` | 에이전트 간 메시지함 | 사내 "메신저" |

### facts 카드에 담긴 추가 정보
단순 텍스트가 아니라, 각 사실마다 다음 정보가 붙습니다.

- `confidence` (신뢰도) — 이 사실을 얼마나 믿는지
- `use_count` (사용 횟수) — 몇 번이나 주입됐는지
- `derived_from` (출처) — 어디에서 파생됐는지
- `superseded_by` (대체됨) — 새 사실로 교체됐는지

이 정보들이 뒤에서 설명할 **"똑똑한 주입"** 과 **"자동 정리"** 의 재료가 됩니다.

## 6. 똑똑한 주입 — "아무거나 다 넣지 않는다"

기억이 쌓이면 전부 넣을 수 없습니다. AI의 입력 창(컨텍스트)은 한정되어 있기 때문입니다.
DAON은 [`_fact_score()`](../api/api/memory_store.py:573)로 각 기억에 점수를 매겨 **상위 20건만** 주입합니다.

점수 계산 방식:

| 요소 | 반영 | 의미 |
|---|---|---|
| **관련성** | 키워드 겹침 × 10점 | 지금 대화 주제와 맞는가 |
| **사용 빈도** | 최대 5점 | 자주 쓰인 검증된 기억인가 |
| **최신성** | 최대 10점 | 최근 기억인가 |
| **신뢰도** | 점수에 곱셈 | 모순 flagged 기억은 감점 |
| **대체됨** | 즉시 제외 | 새 사실로 교체된 옛 기억은 안 넣음 |

게다가 한 종류만 잔뜩 주입되지 않도록 **카테고리별 쿼터**도 둡니다.
(예: general 최대, preference 3건, project 2건)

### Wake-up 기능
마지막 대화로부터 **8시간 이상** 지나고 다시 시작하면,
AI에게 "오랜만에 대화를 재개합니다. 이전 맥락을 이어가세요"라는
**Wake-up 헤더**를 붙여 자연스럽게 이어지게 합니다.

---

## 7. 자동 정리 — "쌓이기만 하지 않는다"

기억 시스템이 망가지는 가장 흔한 이유는 **쓰레기가 쌓여서** 입니다.
DAON은 백그라운드 워커가 주기적으로 스스로 정리합니다.

### 7-1. 중복 제거 (저장 시점)
새 사실을 저장할 때 [`add_fact()`](../api/api/memory_store.py:264)이 LLM으로 검사합니다.

| 상황 | 처리 |
|---|---|
| 완전히 같은 내용 | 저장 안 함 (스킵) |
| 뜻이 같은 내용 | 기존 사실 갱신 |
| 서로 모순되는 내용 | 옛 사실에 "대체됨" 표시 + 새 사실 저장 |
| 완전히 새로운 내용 | 신규 저장 |

### 7-2. 일일 심화 정제
하루에 한 번 [`_run_daily_refine()`](../api/api/memory_store.py:1468)이
비슷한 사실들을 묶고(클러스터링), 합치고, 모순을 해결합니다.

### 7-3. 모순 감지 + 사람 승인
AI가 혼자 결정하기 애매한 경우(예: 서로 충돌하는 두 사실)는
**`memory_review` 검토 대기함**에 올리고 사람이 승인/거부하게 합니다.
AI가 멋대로 중요한 기억을 지우지 못하게 하는 안전장치입니다.

### 7-4. 자동 유지보수
- **1시간마다**: 사실 개수 상한(500건) 초과분 정리
- **24시간마다**: DB 최적화(VACUUM) + 백업 (`memory.db` → `memory.backup.db`)

## 8. 기억은 얼마나 오래 가는가 (보존 기간)

이 시스템의 기억은 **"얼마나 자주 쓰이느냐"** 에 따라 수명이 결정됩니다.
모든 기억이 영원히 남는 것도, 전부 금방 사라지는 것도 아닙니다.

### 사실대로 밝히는 보존 규칙 (코드 기준)

| 기억 종류 | 보존 기간 | 근거 |
|---|---|---|
| **자주 참조되는 핵심 사실** | **사실상 영구** | 쓰일 때마다 `last_used_at`이 갱신되어 삭제 대상에서 계속 빠짐 |
| **안 쓰는 사소한 사실** | **약 90일 후 자동 소멸** | 30일 미사용 시 신뢰도 20% 감소 → 90일 미사용 + 신뢰도 0.3 미만이면 자동 삭제 |
| **사용자 프로필** (이름·직업 등) | **영구** | 삭제 로직 없음. 명시적으로 지우기 전까지 유지 |
| **세션 요약** | **영구** (세션당 1건) | 개수 상한 없음 |

### 구체적으로 일어나는 일
- **매 1시간**마다 점검이 돕니다 ([`_run_maintenance()`](../api/api/memory_store.py:1424)).
  - 사실 카드가 **500건**을 넘으면 가장 오래된 것부터 잘라냅니다.
  - **30일 이상 안 쓴** 사실은 신뢰도를 0.8배로 낮춥니다(감쇠).
  - **90일 이상 안 쓰고** 신뢰도가 0.3 아래로 떨어진 사실은 자동으로 지웁니다.
- 핵심은 **"자주 쓰이는 기억은 절대 늙지 않는다"** 는 점입니다.
  대화에서 계속 참조되는 한 `last_used_at`이 매번 현재 시각으로 갱신되어,
  30일·90일 기준에 걸리지 않습니다.

### 그래서 "중요한 기억"의 정의
이 시스템에서 **중요하다 = 자주 참조된다** 입니다.
사람이 따로 "이건 중요해"라고 표시하지 않아도,
AI가 대화에서 계속 꺼내 쓰는 기억이 자연스럽게 살아남고,
한 번 말하고 다시는 안 쓰는 기억은 서서히 잊힙니다.
사람의 기억이 "자주 떠올리는 것을 오래 기억하는" 방식과 같은 원리입니다.

### "언제 무슨 일을 했는지"도 기억하는가?
**부분적으로 가능합니다.**

- 각 사실 카드에는 `created_at`(학습 시각)이 붙어 "대략 언제 알게 된 사실인지"가 남습니다.
- 세션 요약(`summaries`)은 **세션별 줄거리 + 시각**을 함께 저장하므로,
  "그 무렵 어떤 주제·작업을 다뤘는지"는 AI가 다시 떠올릴 수 있습니다.
- 주입 일지(`fact_usage`)에도 `injected_at`이 남아 "언제 그 기억을 꺼냈는지"가 기록됩니다.

**정밀한 "언제 무슨 일"은 세션 DB가 담당합니다.**
기억 시스템의 시각은 "기억을 학습한 시각"이라 분 단위 정밀도가 낮지만,
별도의 **세션 DB**([`api/api/models.py`](../api/api/models.py))에는
모든 대화 메시지가 **메시지별 `timestamp`와 함께 원문 그대로** 저장됩니다.
"2026년 7월 28일 15시에 A 파일을 수정했다" 같은 정밀 작업 일지는 여기에 남습니다.

### 세션 DB는 지우지 않는 한 영구 보존된다
이 부분이 중요합니다. 세션 DB에는 **자동 만료·자동 정리 로직이 없습니다.**
코드를 확인한 결과, 세션이 사라지는 경로는 오직 **사용자가 명시적으로 지울 때**뿐입니다.

- [`delete_session()`](../api/api/models.py:389) — 사용자가 세션을 삭제할 때만 호출
- 시간 경과에 따른 자동 삭제(purge/retention) 로직 **없음**

따라서 세션 DB의 대화 원문과 시각 정보는 **지우지 않는 한 1년 뒤에도, 그 이상에도
그대로 남아 있습니다.** 기억 시스템(facts)이 "자주 쓰는 것만 남기는 선별 기억"이라면,
세션 DB는 **"모든 것을 남기는 완전한 기록"** 입니다.

> 정리하면 DAON에는 두 층의 기억이 있습니다.
> - **세션 DB** = 지우지 않는 한 영구 남는 **완전한 작업 일지** (정밀 타임라인)
> - **기억 시스템(facts)** = 자주 쓰는 핵심만 추려 오래 남기는 **선별 작업 기억**
>
> 그래서 "1년 전 언제 어떤 일을 했는지"는 세션 DB에서,
> "이 사람이 누구이고 무엇을 선호하는지"는 기억 시스템에서 답을 찾습니다.

### 세션을 바꾸면 이전 작업이 이어지는가?
**이어집니다. 단, 두 가지 경로로 나뉩니다.**

새 세션([`new_session()`](../api/api/models.py:139))은 **빈 상태**로 시작합니다.
이전 세션의 대화 원문을 자동으로 통째로 가져와 이어붙이지는 않습니다.
대신 다음 두 경로로 연속성을 확보합니다.

1. **기억 시스템이 자동으로 잇는다 (선별 연속)**
   새 채팅이 시작되면 [`build_memory_prompt()`](../api/api/streaming.py:1138)가
   이전 세션들에서 추출한 facts·profile·summaries를 시스템 프롬프트에 주입합니다.
   그래서 세션을 새로 열어도 "이 사람이 누구인지, 무엇을 선호하는지,
   어떤 작업을 해왔는지" 같은 **핵심 맥락은 자동으로 이어집니다.**

2. **이전 세션을 다시 열어 그대로 잇는다 (원문 연속)**
   특정 세션을 선택하면 [`get_session()`](../api/api/models.py:124)이
   그 세션의 **전체 대화 원문을 그대로** 불러옵니다.
   이 안에서는 대화가 끊기지 않는 완전한 연속 작업이 가능합니다.

> 한 문장으로: **새 세션은 "기억(요약)"으로 잇고, 다시 연 세션은 "원문"으로 잇습니다.**
> 두 경로 모두 세션 DB가 지우지 않는 한 영구 보존되기에,
> 언제든 과거 작업을 이어서 할 수 있습니다.

## 9. 사람은 어떻게 보나 (API / UI)

기억 시스템은 다음 API로 조회·관리할 수 있습니다.
(라우팅: [`api/api/routes/admin_routes.py`](../api/api/routes/admin_routes.py))

| API | 용도 |
|---|---|

| `GET /api/memory/profile` | 사용자 프로필 보기 |

| `POST /api/memory/profile/set` | 프로필 항목 저장 |
| `POST /api/memory/review/resolve` | 검토 항목 승인/거부 |

## 10. 안정성 설계 — "기억이 고장나도 채팅은 산다"

이 모듈의 가장 중요한 공학적 원칙은 **순수 부가(pure additive)** 입니다.

> 기억 시스템에서 무슨 오류가 나도, 기존 채팅·에이전트 동작은 절대 깨지지 않는다.

이를 위해 모든 공개 함수를 `try/except`로 감싸, 실패하면 조용히 빈 값을 반환합니다.
기억은 "있으면 좋은 것"이지, "없으면 시스템이 멈추는 것"이 아니라는 설계입니다.

## 11. 요약

- DAON 기억 시스템은 **AI의 작업 기억**입니다. 사람 노트가 아닙니다.
- 대화 종료 시 **자동 추출**, 다음 대화 시 **자동 주입** — 사람은 거의 개입하지 않습니다.
- 저장만 하는 게 아니라 **중복 제거·랭킹 주입·자동 정제·모순 감지**까지 스스로 합니다.
- 모든 것은 `memory.db` 한 파일에, 백그라운드 워커가 안전하게 처리합니다.
- 기억 모듈이 고장나도 채팅은 정상 동작합니다 (순수 부가 원칙).
- **기억 수명은 사용 빈도로 결정됩니다.** 자주 쓰는 핵심 기억은 사실상 영구,
  안 쓰는 사소한 기억은 약 90일 후 자동 소멸, 프로필·요약은 영구 보존됩니다.

## 12. 결론 — 1년 후에도 기억하는가?

**사실대로 답하면: "무엇을 기억했느냐"에 따라 다릅니다.**

### 1년 후에도 살아남는 기억
- **자주 대화에서 꺼내 쓰는 핵심 사실** — 예를 들어 "사용자는 파이썬 개발자",
  "프로젝트 A를 진행 중", "한국어 답변 선호" 같은 것은 매 대화마다 참조되므로
  `last_used_at`이 계속 갱신되어 **1년 뒤에도, 그 이상에도 그대로 남습니다.**
- **사용자 프로필**(이름·직업·선호 언어 등)과 **세션 요약**은 삭제 로직 자체가 없어
  **영구 보존**됩니다.

### 1년 후면 사라지는 기억
- 한 번 언급하고 다시는 쓰지 않은 사소한 사실은 **약 90일** 안에 신뢰도가 깎이다
  자동 삭제됩니다. 1년 뒤에는 남아있지 않습니다.

### 핵심 한 문장
> **"중요한 일은 1년 후에도 기억하고, 사소한 일은 스스로 잊는다."**

DAON은 모든 것을 무한정 쌓는 저장소가 아닙니다.
사람이 자주 떠올리는 일을 오래 기억하고 흐릿한 일은 잊듯,
**AI가 계속 참조하는 기억만 골라 오래 살리는 "살아있는 작업 기억"** 입니다.
그래서 1년 뒤에도 "언제 어떤 일을 했는지" 같은 핵심 맥락은 그대로 이어집니다.
