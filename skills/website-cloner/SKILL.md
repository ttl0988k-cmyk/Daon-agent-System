# 웹사이트 클론 (Website Clone)

**⚠️ 먼저 목적을 판정한다.**

| 목적 | 이 스킬을 쓰나 | 작업자 | 검증 기준 |
|---|---|---|---|
| **동일 복제** — "이 페이지 그대로" | ✅ 이 스킬 (§1~§4) | 라온 가능 | 픽셀 차이율 · MAE · 폰트 동일 |
| **모방** — "이 사이트 같은 느낌으로 다른 걸" | ❌ **`rea-web-app-reverse-and-restore` §5-C로 SPEC.md 작성 → 빌/작업장/하네스/워커 인계** | **라온=명세만** (tainted) | **기능 동등성** (바이트/픽셀 일치는 오판) |

모방 작업에서 폰트·색을 내 것으로 바꾼 결과를 이 스킬의 픽셀 비교로 채점하면 **정상 작업이 FAIL로 찍힌다.** 목적이 모방이면 SPEC.md가 산출물이고, 구현은 SPEC.md만 받아서 새로 만든다. **원본을 관찰한 라온이 구현까지 하면 클린룸이 깨진다.**

**핵심 원칙: 소스를 먼저 일치시킨 뒤, 그 다음에 새 디자인 방향을 더한다.**
스크린샷·iframe·다운로드한 프로덕션 번들은 **참고자료**지 구현물이 아니다. 납품물은 동작하고 편집 가능한 코드다.

재구축 순서는 항상 동일하다:
**① 작업 지도화 → ② 만들기 전에 관찰 → ③ 1차 완성본 → ④ 비교·수리 반복 → 납품(증거 포함)**

## 0. 사전 준비 (다온 환경)

### 증거·산출물 배치
| 종류 | 경로 |
|---|---|
| 페이지 브리프/조사 기록 | `docs/research/<site>/` |
| 소스/로컬 비교 스크린샷 | `docs/design-references/` |

### 다온 도구 배치
| 용도 | 도구 |
|---|---|
| 페이지 관찰·상태 조작·계측 | `ego-browser` 스킬 (Playwright 기반) |

| 정적 추출·에셋 수집 | 이 스킬의 `scripts/*.py` |
| 헤드리스 캡처 | Chrome `--headless=new --screenshot` 또는 `scripts/capture_page.py` |

⛔ GitHub/소스 저장소 분석은 브라우저가 아니라 터미널(`git clone`, `curl`)로.
⛔ 스켈레톤 브라우저(browser_*)는 대표님이 "스켈레톤으로"라고 명시할 때만.

# 1) 정적 1차 수집: HTML/CSS/폰트/에셋 URL/manifest

# 2) 렌더 기반 캡처+계측: 뷰포트/스크롤/상태별 스크린샷 + computed style 덤프
python "$SK/capture_page.py" https://example.com --out docs/design-references \
    --viewports 1440x900,390x844 --fullpage --measure "header,nav,h1,.hero"

# 2-b) 브레이크포인트 탐지(폭 스윕) + hover/클릭 상태 캡처
python "$SK/capture_page.py" https://example.com --out docs/design-references \
    --sweep ".cards" --sweep-range 360,1440,20 \
    --hover ".btn" --click ".acc:nth-child(2) button"

# 3) 매니페스트 기반 에셋 다운로드(실제 포맷 판정·확장자 교정)

    --dest public/sites/example --referer https://example.com

# 4) 소스↔로컬 비교(몽타주 + 차이 히트맵 + 수치)

## 1. 작업 지도화 (Map the work)

프로젝트 지침, **실제** 프레임워크·스크립트(`package.json`, `next.config`, `vite.config`), 기존 라우트를 읽는다. 소스 URL은 브라우저로 열되, **추출은 가능하면 HTTP 직접·에셋 도구·API를 우선**하고 브라우저는 외형과 동작 확립에 쓴다.

**소스→로컬 라우트 맵**과 페이지별 소유 파일을 짧게 기록한다. 출처(origin)·페이지·다운로드에 서로 다른 이름을 주고, 읽을 만한 이름이 충돌하면 포트나 URL 해시를 붙인다.

- 첫 루트 클론은 손대지 않은 템플릿 홈페이지를 대체해도 된다.
- 한 origin의 여러 페이지는 **소스 경로명을 보존**한다. 쿼리/프래그먼트 변형은 보통 같은 라우트의 상태이므로 그 상태를 재현한다.
- 기존에 작성된 라우트/에셋은 보존한다. 요청받았을 때만 갱신하고, 요청받지 않은 라우트 충돌은 **대체 전에 해결**한다.
- 기존 클론에 페이지를 추가할 때는 기존 페이지가 쓰는 스타일을 갈아엎지 말고 레이아웃·전역 스타일을 **확장**한다.
- 다른 origin은 사용자가 통합 앱을 원하지 않는 한 별도 앱으로 만든다. 통합 시에는 라우트 프리픽스·폰트·스타일·레이아웃을 스코프 분리한다.
- 프레임워크 문법과 충돌하는 URL 세그먼트(`_`, `@`, 대괄호, 괄호)는 지원 수단으로 이스케이프하고 **실제 요청 URL로 검증**한다.

기존 클론은 유용한 출발점이다. 현재 소스와 비교하고 무엇을 재사용했는지 기록한다.
**완료 조건: 요청된 모든 URL에 목적지가 생기고 파일 소유권이 명확해질 때.**

## 2. 만들기 전에 관찰 (Observe before building)

데스크탑·모바일 폭에서 페이지 전체를 본다. 위→아래로 스크롤해 **lazy 미디어를 로드하고 sticky/pinned 씬을 노출**시킨다. 그 다음 메뉴·탭·아코디언·캐러셀·hover 상태·주요 링크를 실제로 조작한다.

**스크롤·클릭·hover·시간 중 무엇이 변화를 구동하는지 구분하라.** 스크롤 구동 섹션을 클릭으로 흉내내면 그것은 다른 제품이다.

관찰 1회는 **규칙의 표본 1개**일 뿐이다. 한 번의 렌더링에서 추론하지 말고 **선언된 값**(computed style, CSS 변수, 라이브러리의 실제 옵션)을 읽는다. 뷰포트 폭(디자인보다 넓은 폭 포함)·높이·입력·상태를 변주해 무엇이 변화를 구동하는지 확정될 때까지 반복한다.

방문자가 쓰는 입력(휠·터치·키보드·포인터)으로 페이지를 구동한다. **스크립트 스크롤은 smooth scrolling처럼 그 입력에 붙은 동작을 우회**한다.

소스 스크린샷은 뷰포트·스크롤 위치·인터랙션 상태를 라벨로 남긴다. 대체 상태의 콘텐츠/에셋도 캡처한다. **간결한 페이지 브리프 1장**을 유지: 섹션 순서, 타이포그래피, 레이아웃 치수, 에셋 매핑, 인터랙션. 독립 빌더에게 도움이 될 때만 섹션 브리프를 추가한다.

추출·상태 비교 상세는 [inspection-guide](references/inspection-guide.md).
**Framer 생성 페이지, sticky 씬, 리빌 애니메이션, 애니메이션 미디어**는 [framer-and-motion](references/framer-and-motion.md).
다온 도구로 계측·캡처하는 실전 레시피는 [daon-adaptation](references/daon-adaptation.md).

### 모션 드라이버 → 구현 매핑

드라이버를 확정했으면 아래 표로 구현 방식을 고른다. **드라이버를 잘못 고르면 구현 전체가 틀린다** (스크롤 구동을 클릭 토글로 만들면 다른 제품).

| 드라이버 | 관찰할 증거 | 구현 |
|---|---|---|
| **시간(time)** | 반복 주기, 일시정지, 방향, 루핑 미디어 | CSS `@keyframes` / `<video>` / 애니메이션 라이브러리 |
| **스크롤 리빌** | 진입 경계값, 시작·종료 위치, 역스크롤 시 재생 여부 | `IntersectionObserver` + CSS |
| **연속 스크롤** | 진행률, 핀(pin) 지속 거리, 레이어별 속도 | scroll progress → CSS 변수 또는 라이브러리 |
| **클릭/hover** | 대체 콘텐츠, 트랜지션, 닫힘/이동 | 상태(React state 등) + CSS |
| **포인터/캔버스** | 반응 방식, 렌더러·미디어 정체 | 동일 렌더러 재현, 불가하면 **근사임을 고지** |

- **핀(pinned) 씬은 `position: sticky`만으로 끝나지 않는다** — 스크롤 거리와 해제(release) 동작까지 재현해야 한다.
- 애니메이션처럼 보이는 것이 **실제로는 영상**인 경우가 있다. 원본 미디어가 있으면 그걸 쓴다.
- 스크롤 라이브러리 식별: **Lenis**를 쓰면 `html`에 `lenis` 클래스가 붙거나 `window.lenis` 전역이 옵션을 노출한다 → 그 옵션값을 그대로 재현한다. 이런 라이브러리가 깔리면 **스크립트 스크롤은 무력화**되므로 실입력(휠/터치)으로 구동해야 한다.
- **양방향(위·아래)과 모바일을 모두 관찰**한다. 한 방향만 보고 만들면 역재생에서 깨진다.

**완료 조건: 모든 섹션과 의미 있는 상태가 구축 가능한 증거를 갖추고, 확보 불가한 디테일은 식별되어 있을 때.** 대용량 DOM 덤프는 페이지를 보는 것을 대체하지 못한다.

## 3. 1차 완성본 구축 (Build a complete first pass)

폰트, 페이지 폭, 색, 에셋, 라우트, 페이지 전역 동작, 공유 컴포넌트를 **먼저** 세운다. 공유 컴포넌트는 관찰된 **모든 상태**(hover, focus, 브레이크포인트)를 포함해 만들어 빌더가 그대로 재사용하게 한다. 맞는 컴포넌트는 재사용한다. 레이아웃·단순 모션은 CSS를, 소스 동작이 요구하면 애니메이션 라이브러리를 쓴다.

실제 콘텐츠로 일관된 섹션을 만든다. **공유 파일의 소유자가 정해진 뒤에** 독립 페이지/섹션을 위임한다. 빌더에게는 스크린샷, 관련 치수/상태 메모, 에셋 경로, 목적지 파일, **구체적 완료 기준**을 준다. 정확한 파일 참조가 담긴 간결한 브리프면 충분하다 — 고정된 에이전트 수나 컴포넌트별 문서화는 요구하지 않는다.

범위 내 인터랙션을 재현한다. 실제 외부 목적지는 보존한다. 로컬 라우트가 범위에 포함되면 링크를 로컬 라우트로 바꾸고, 범위 밖 목적지는 소스를 가리키게 두고 **고지**한다. **보이는 컨트롤은 약속한 동작을 반드시 수행해야 한다.**

통합 슬라이스마다 해당 프로젝트 체크를 실행한다(빌드·린트·타입체크).
**완료 조건: 요청된 모든 섹션/라우트가 실제 에셋으로 렌더되고 중요한 컨트롤이 동작할 때.**

### 다온 분업(선택)
- 프라다: 레이아웃/타이포/컬러 토큰, 반응형 브레이크포인트
- 빌: 라우트·데이터 배선·API·빌드 설정
- 셜록: 동등성 검증(치수·상태·오버플로·에셋 404)
- ⚠️ 공유 파일 소유자를 먼저 정하지 않고 병렬 위임하면 충돌한다.

## 4. 비교·수리·반복 (Compare, repair, repeat)

소스와 로컬 페이지를 **같은 뷰포트·스크롤 위치·상태**에서 연다. 폰트·미디어·리빌 애니메이션이 **안정화될 때까지 기다린다**. 2단계에서 규칙 변화가 발견된 모든 지점과 **디자인보다 넓은 뷰포트**를 포함해 페이지 전체를 검토하고, 스크롤·포인터 동작은 실제 입력으로 판정한다. 나란히 붙인 몽타주는 **어긋남의 위치**를, 원본 크기 섹션은 **디테일**을 확립한다.

**가장 큰 시각 차이부터 고친다:**
1. 지오메트리(폭·높이·정렬)
2. 누락 섹션/레이어
3. 타이포그래피·줄바꿈
4. 에셋 크롭/해상도
5. 간격·모션

수정 후 영향받은 뷰를 **재확인**한다. 애니메이션 영역은 초기·활성·정착 상태로, 필요하면 **역스크롤**까지 비교한다.

실제 로컬 워크플로를 훑는다: 클론한 라우트 간 이동, 모바일 메뉴, 탭/아코디언 상태, 캐러셀 경계, 주요 액션, 미디어 컨트롤, 관찰된 스크롤 연동 전환. **런타임 에러·누락 에셋·가로 오버플로**를 확인한다. 페이지를 추가했으면 기존 라우트가 여전히 동작하는지 검증한다. 클래스명에 대한 단언 대신 **경계 지점에서 소수의 브라우저 실측**을 쓴다.

프로덕션 체크를 실행한다. **완료는 빌드 성공 '그리고' 렌더 비교 둘 다**를 요구한다. 검증하지 않은 결과를 "픽셀퍼펙트"라고 부르지 말고, 남은 차이를 정확히 서술한다.

### 비교 판정 기준 (`compare_shots.py` 출력 해석)

| diff 비율(임계 16/255) | 판정 | 조치 |
|---|---|---|
| **< 2%** | PASS (근접) | 남은 차이는 AA·폰트 힌팅·서브픽셀. 구조 확인 후 종료 |
| **2 ~ 8%** | WARN (부분 불일치) | 간격·타이포·에셋 크롭·radius |
| **> 8%** | FAIL (구조적 차이) | **지오메트리 → 섹션 누락** 순으로 먼저 |

`size_mismatch`가 뜨면 그것이 1차 신호다(폭·높이·줄바꿈 차이). `diff_bbox`가 화면 절반 이상이면 섹션 누락이나 레이아웃 붕괴를 의심한다. 픽셀 0을 목표로 삼지 않는다.

### ⭐ 폰트 폴백 함정 — WARN(2~8%)의 최대 단일 원인

**증상:** diff 2~8% WARN. 스크린샷을 `vision_analyze`로 봐도 "정상"으로 보인다. 그런데 `size_mismatch`에서 h1 폭이 원본 521px vs 로컬 558px처럼 **7% 넓게** 나온다.

**원인:** Next.js `next/font`는 폰트를 `@font-face`로 넣는 데 그치지 않고, `<html class="__variable_a1b2c3 __variable_d4e5f6">` 같은 클래스와 함께 `--font-work-sans`, `--font-noto-sans-kr` **CSS 변수**를 `<html>`에 심는다. 바디 CSS는 `font-family: var(--font-work-sans), sans-serif`. 클론에서 이 클래스/변수를 안 옮기면 CSS가 **시스템 기본 폰트로 조용히 폴백**한다 — 폰트 파일을 100개 다 받아놨어도 마찬가지다.

**탐지 (눈으로는 못 잡음 → computed style 대조가 유일):**
```javascript
// 원본과 로컬 양쪽에 같은 스크립트 실행
const h1 = document.querySelector('h1');
getComputedStyle(h1).fontFamily          // 'Work Sans' vs 'Times New Roman'
getComputedStyle(document.documentElement).getPropertyValue('--font-work-sans')
document.fonts.size                       // 로드된 @font-face 수
```
`document.fonts`에 엔트리가 있는데 computed `fontFamily`에 그 이름이 없으면 = 변수/클래스 미연결 확정.

**수정:** `<html>`에 원본의 `__variable_*` 클래스를 그대로 붙이고, 각 클래스가 변수를 정의하게 한다.
```css
.__variable_a1b2c3 { --font-work-sans: 'Work Sans', 'Work Sans Fallback'; }
```
변수만 정의하고 클래스를 `<html>`에 안 붙이는 실수도 흔하다 — 둘 다 필요하다.

**실측 효과(2026-11-01 해볼까 클론):** 3.96% → **0.07%**. 그 외 코드는 한 줄도 안 바꿨다. 즉 2~8% WARN에서 지오메트리·섹션을 먼저 뒤지기 전에 **폰트 computed 값부터 확인**하면 헛수고를 크게 줄인다. `fonts_loaded` 목록에 `X Fallback`이 찍혀 있으면 정상 로드로 간주한다.

### 인터랙션 증거는 상태 전환으로 남긴다

정적 캡처가 0.07%로 맞아도 "동작한다"는 증거가 아니다. 예시 선택·탭 전환·폼 제출 같은 컨트롤은 클릭 후 **DOM 텍스트가 실제로 바뀌는지**를 출력해 로그로 남긴다(예: 예시 3종 각각 클릭 → 아이디어 문구·배지 목록 변화 확인). 콘솔/`pageerror`/`requestfailed` 카운트가 전부 0인 상태에서 이 로그가 있어야 Gate 2·3를 통과한 것으로 본다.

## 납품 (Deliver)

다음을 함께 돌려준다:
1. **실행/프리뷰 방법**
2. **소스→로컬 라우트 맵**

5. **남은 시각·기능 격차** — 미구현 셰이더/캔버스 동작은 정지 이미지로 대체 증명하지 말고 이름을 밝힌다

재사용 템플릿을 유지하는 경우 레퍼런스 클론은 별도 앱으로 분리한다.

## 다온 검증 게이트 (AGENTS.md 연동)

| Gate | 내용 | 통과 기준 |
|---|---|---|
| **Gate 1** | 빌드/런타임 무결성 | `npm run build` 성공, 콘솔 에러 0, `NaN`/`undefined`/깨진 태그 0 |
| **Gate 2** | 시각 판독 | `vision_analyze`로 소스/로컬 이미지를 **직접 판독**, 3개 이상 뷰포트(데스크탑·태블릿·모바일) 확인 |
| **Gate 3** | 완성도 대조 | 섹션 누락 0, 컨트롤 동작, 모바일 가로 오버플로 0, 에셋 404 0 |

⚠️ **텍스트 지표만으로 완료 선언 금지.** 스크린샷을 만들었으면 반드시 `vision_analyze`에 넣어 형태·겹침·잘림을 눈으로 확인한다.
⚠️ **미검증 항목은 "⚠️ 미완"으로 명시**한다. 코드만 반영하고 "다 했습니다" 보고 금지.
